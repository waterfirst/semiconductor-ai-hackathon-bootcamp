# 모두의 창업 2차 · Virtual Fab 사업계획서 전략 초안

작성일: 2026-08-23  
상태: 공식 신청양식 반영 전 내부 정본  
신청 후보: **기술특화 트랙** / 기창업자 이종창업
사업 주체: 별도 확인 전까지 기존 사업자 업종 추가 보류

## 1. 신청 아이템

### 권장 명칭

**FAB-JUDGMENT Industry Twin — 산업·SCM 지식과 공정 판단을 연결하는 AI 가상팹**

### 한 문장 정의

팹 경험이 없는 반도체 취업준비생이 출처가 표시된 산업동향·현업 용어·SCM 기업지도를 이해한 뒤, 합성 공정 데이터와 AI로 원인·실험·조치를 판단하고 그 과정을 교육기관이 평가 가능한 역량 증거로 전환하는 웹 기반 가상 실험실이다.

### 기술특화 정의

본 사업은 온라인 강의나 산업정보 챗봇이 핵심인 일반 교육사업이 아니다. 핵심 제품은 **공식 산업정보를 출처·기준시점과 함께 구조화하고, 재현 가능한 제조 이상 데이터를 생성하며, 사람–AI의 판단 과정을 서버에서 검증·채점하는 시뮬레이션 SaaS 엔진**이다. 반도체 교육은 이 엔진의 첫 번째 수직시장이다.

핵심 기술 모듈:

1. `scenario_version + seed` 기반 결정적 합성데이터·함정 생성기
2. 정답을 브라우저에 공개하지 않는 서버측 진단·채점 엔진
3. Tool·Lot·공간·시간·품질을 연결하는 증거 분석 구조
4. AI 응답의 채택·수정·기각과 사람 검증근거를 남기는 감사 로그
5. 실험·분석 선택으로부터 분리 Holdout을 계산하는 검증 엔진
6. 행동기록을 문제해결 역량으로 변환하는 서버측 평가 API
7. 공정 시나리오를 데이터·규칙·렌더러로 분리하는 확장형 저작구조
8. 산업지표·용어·기업·공정·제품의 관계를 연결하는 반도체 지식그래프/RAG
9. 출처·기준시점·신뢰등급을 보존하고 API 변경에 대응하는 데이터 provenance 계층

공공 NCS·산업안전·무역통계와 기업 공시는 단순 읽을거리가 아니라 시나리오의 용어·회사 역할·의사결정 맥락을 구성하는 입력원이다. 다만 공개 데이터 자체를 독점 기술로 과장하지 않고, **서로 다른 데이터를 근거가 추적되는 학습 시나리오와 행동평가로 변환하는 구조**를 기술 차별점으로 제시한다.

### 사용하지 않을 표현

- 세계 최초 가상팹
- 실제 팹을 완전히 대체
- 실제 기업 공정과 동일
- SK하이닉스·삼성디스플레이 공식 교육
- AI가 불량 원인을 자동 확정
- 사용만 하면 취업 또는 성과를 보장

## 2. 해결하려는 문제

### 학습자의 문제

- 반도체 취업준비생은 실제 팹·장비·공정 데이터에 접근하기 어렵다.
- 공정 이론을 배워도 이상 발생 시 무엇을 먼저 확인하고 어떤 실험을 설계할지 연습하기 어렵다.
- 최신 산업동향을 접해도 그 변화가 공정·직무·채용에 무엇을 뜻하는지 연결하기 어렵다.
- Fab·장비·재료·팹리스·파운드리·OSAT 등 SCM 용어와 회사별 역할을 단편적으로 암기한다.
- 고객·공급사 관계를 출처가 있는 사실과 업종상 추론으로 구분하기 어렵다.
- 생성형 AI를 사용해도 답을 복사했는지, 데이터를 검증하고 판단을 수정했는지 스스로 증명하기 어렵다.

위 항목은 렛유인 특강과 강의 운영에서 반복 관찰한 **초기 문제 가설**이다. 학생 표본조사 전에는 전체 시장의 확정된 수요로 표현하지 않는다.

### 교육기관의 문제

- 완성된 보고서만으로는 학생의 문제 정의, 가설 수정, 분석비용 판단과 AI 검증 습관을 관찰하기 어렵다.
- 실제 기업 기밀 없이도 반복 운영할 수 있는 반도체 문제해결 실습과 객관적 평가자료가 필요하다.

### 아직 검증해야 할 가정

- 학생이 이 문제를 유료로 해결하고 싶어 하는가.
- 산업동향·현업 용어·SCM 기업정보 중 어떤 정보의 우선순위가 가장 높은가.
- 정적 산업정보를 가상팹 사건과 연결했을 때 이해도와 재사용 의향이 실제로 높아지는가.
- 교육기관이 기수별 라이선스 또는 시나리오 제작비를 지불할 의향이 있는가.
- 가상 시나리오의 역량 증거가 강사 평가와 일치하는가.

위 항목은 시장 사실로 단정하지 않고 파일럿과 인터뷰로 검증한다.

## 3. 고객 정의

- **사용자:** 반도체 공정·소자·양산기술·장비 직무를 준비하는 대학생과 취업준비생
- **구매자:** 반도체 교육기관, 대학 부트캠프, 지자체 취업교육 운영기관
- **수혜자:** 강사·교육기획자·학습자
- **초기 검증 협력 후보:** 렛유인에듀
- **장기 확장 후보:** 기업 신입교육 및 비기밀 문제해결 훈련

렛유인과의 논의·특강 경험은 고객 접점의 증거이며, 계약 또는 도입 확정으로 표현하지 않는다.

## 4. 해결 방식

1. **Industry Brief:** 기준일과 출처가 표시된 반도체·제조장비 무역지표와 주요 공시 변화를 짧게 읽는다.
2. **Term Graph:** 현업 용어를 정의만 암기하지 않고 공정·장비·재료·직무와 연결해 확인한다.
3. **SCM Map:** Fabless·IDM·Foundry·Fab·장비·재료·OSAT·고객의 역할과 공개 기업정보를 탐색한다.
4. **Virtual Fab Mission:** 실제 형식을 닮았지만 기밀이 없는 합성 공정 CSV와 사건을 받는다.
5. 결측·중복·단위오류·미끼 변수를 감사하고 Tool·Lot·공간·시간 분포를 분석한다.
6. 학습자는 공정·장비·재료·SCM 키워드를 사용해 AI와 8–15회 경쟁 가설·반증 토론을 진행한다.
7. AI 답을 채택·수정·기각하고 사람의 검증 근거와 사용한 출처를 기록한다.
8. 제한된 예산과 시간 안에서 DOE와 분석 도구를 선택하고 Holdout으로 조치를 검증한다.
9. 산업맥락이 포함된 의사결정 경로, 역량 증거, 최종 면접 PT를 내려받는다.

### 기업·SCM 정보 표시 원칙

- 기업명·사업영역·재무·공시는 OpenDART 등 원문 링크와 기준일을 함께 표시한다.
- 특정 고객·공급사 관계는 공시나 공식 발표에서 직접 확인되는 경우만 `공식 확인`으로 표시한다.
- 제품군과 업종을 바탕으로 연결한 관계는 `분류` 또는 `추론`으로 분리하고 단정하지 않는다.
- AI가 만든 문장은 출처 없는 기업 사실로 저장하지 않는다.
- 오래된 데이터에는 갱신일과 `정보 노후화` 경고를 표시한다.

### 초기 데이터 원천

- **OpenDART:** 기업개황, 공시검색, 정기보고서와 재무정보
- **관세청 공공데이터:** 반도체·반도체 제조용 장비의 10일 단위 잠정 수입지표
- **NCS 공공데이터:** 직무·능력단위·훈련정보를 용어와 역량체계에 연결
- **KOSHA 공공데이터:** 제조업 산업재해 사례를 안전 시나리오에 활용
- **KIPRIS Plus:** 특허·기술동향은 호출비용과 라이선스를 확인한 뒤 선택적으로 연동

각 원천은 서버에서 수집하고 `source_url`, `effective_date`, `fetched_at`, `schema_version`, `confidence`를 저장한다. 외부 API가 중단돼도 수업이 멈추지 않도록 검증된 스냅샷과 스키마 계약시험을 유지한다.

## 5. 현재 MVP 증거

- 공개 주소: <https://waterfirst.pro/virtual-fab/>
- 대표 PHOTO 시나리오: 2,969행 합성 데이터
- `scenario_version + seed` 기반 결정적 재현
- 브라우저에 공개하지 않는 서버 정답키와 7항목 채점
- Tool·Lot·`radius_mm` bin·slot·시간 그룹 분석
- 미끼 Tool, edge 영역, onset Lot, 결측·단위·중복 함정
- AI 8–15회 문답과 회차별 사람 검증
- 비용·시간·필수 정보영역을 반영한 분석 선택
- 서버 Holdout과 최종 적용 범위 판단
- 5개 영역의 역량 증거 리포트
- 최종 Markdown 조사기록과 오프라인 HTML 면접 PT
- 추가 5개 공정 시나리오의 학습 흐름 및 데이터 미리보기
- Python API 테스트 27개 통과
- Playwright 데스크톱 전체 학습 흐름 통과

테스트 통과는 소프트웨어 작동 증거이며 교육 효과나 고객 지불의향을 입증하지 않는다.

### 기존 기업·산업 분석 자산 연계

운영 중인 Alpha Hunter에는 반도체·AI 인프라 기업의 공시, 실적, 제품, 경쟁구도와 밸류체인을 조사하는 기업발굴 작업이 축적돼 있다. 이를 별도 투자서비스로 결합하지 않고 **Industry Twin의 기업·SCM 후보 발굴 파이프라인**으로 제한해 재사용한다.

- 재사용: 기업명, 공식 사업영역, 제품군, 공정단계, 경쟁사, 공시·IR 원문, 기준일
- 교육용 변환: SCM 역할, 관련 공정·장비·재료, 관련 직무, 가상팹 사건과의 연결
- 제거: 주가 모멘텀, SEPA 점수, 목표가, 매수·매도 판정, 포트폴리오 정보
- 재검증: 기존 보고서 문장이 아니라 DART·SEC·기업 IR 등 1차 원문을 다시 확인한 뒤 등록

첫 후보군은 HPSP, ISC, 프로텍, Onto Innovation, Amkor처럼 기존 분석에서 발견한 전공정 장비·검사계측·후공정 기업이다. 이는 기업관계나 기술사실이 이미 검증됐다는 뜻이 아니라, Industry Twin의 1차 원문검증 대상으로 삼는다는 의미다.

이 연결로 `기업 발굴 → 원문 검증 → SCM 지식그래프 → 가상팹 시나리오 → 학생 판단 로그`의 데이터 순환구조를 만든다.

## 6. 차별점

| 비교 기준 | 일반 공정 강의 | 일반 생성형 AI 실습 | FAB-JUDGMENT |
|---|---|---|---|
| 공정 이상 의사결정 | 설명 중심 | 범용 질의 | 사건·제약·선택 기반 |
| 데이터 함정 | 제한적 | 입력에 의존 | 결측·단위·중복·미끼 내장 |
| AI 검증 | 확인 어려움 | 답변 생성 중심 | 채택·수정·기각 근거 기록 |
| 실패 활용 | 오답 처리 | 대화 종료 | 동일 seed로 경로 재실험 |
| 평가 산출물 | 시험·보고서 | 프롬프트·답변 | 서버 행동기록·역량 증거·PT |
| 산업·SCM 맥락 | 별도 이론자료 | 검색 결과에 의존 | 출처·기준일이 있는 기업지도와 사건 연결 |

차별점은 3D 공간 자체가 아니라 **반도체 판단 행동을 재현·관찰·평가하는 구조**다.

### 기술특화 경쟁력

- 단순 LLM 질의가 아니라 데이터·질문·행동·검증을 하나의 세션 상태로 연결한다.
- 동일 seed에서는 입력과 정답이 재현되지만, seed가 바뀌면 원인·미끼·onset이 달라져 암기 공략을 어렵게 한다.
- 정답키·API 키는 프런트엔드에 노출하지 않고 서버에서만 사용한다.
- AI 사용 횟수가 아니라 답변을 어떤 증거로 채택·수정·기각했는지 평가한다.
- 완성 보고서만 보는 대신 과정 로그에서 역량 증거를 산출한다.
- 산업정보를 따로 보여주는 데 그치지 않고, 해당 정보가 공정 사건의 가설·DOE·조치 판단에 쓰였는지 기록한다.
- 기업관계를 `공식 확인·분류·추론`으로 구분해 생성형 AI의 사실 혼합을 줄인다.
- 기존 기업발굴 자산을 재사용하되 투자판단과 교육용 산업지식을 데이터 계약 단계에서 분리한다.
- 렌더러와 시나리오 규칙을 분리해 반도체 외 제조·안전 직무로 확장할 수 있다.

## 7. 사업모델 가설

### 우선순위 1 · B2B2C

- 교육기관 기수별 이용권
- 수강생 수에 따른 라이선스
- 기관 전용 시나리오 제작비
- 강사용 대시보드·평가 리포트 구독

### 우선순위 2 · B2C

- 개인용 시나리오 팩
- 면접 PT·문제해결 포트폴리오 패키지

가격은 아직 확정하지 않는다. 렛유인·대학·학생 인터뷰에서 현재 대체비용, 예상 사용빈도와 지불의향을 조사한 뒤 제시한다.

## 8. 파일럿 검증 계획

### 1차 · 렛유인 특강 참여자 자율 파일럿

- 인원: 5–10명
- 시간: 60분 내외
- 방식: 니즈·산업맥락 사전진단 → Industry Twin 카드 → 대표 PHOTO 시나리오 → 사후진단·사용성 설문
- 개인정보: 이름·이메일·학교·회사 수집 금지, 무작위 참여코드만 사용
- 기업자료: 실제 회사 데이터·Spec·Recipe 업로드 금지

### 성공 기준

- 80% 이상 강사 개입 없이 대표 시나리오 완주
- 중대한 데이터·세션 손실 0건
- 사전·사후 동일 역량 rubric의 평균 개선
- 70% 이상이 기업·용어·산업지표의 출처와 기준일을 찾아 설명
- 70% 이상이 `공식 확인`과 `추론` 관계를 구분
- 70% 이상이 AI 답을 한 번 이상 채택 외 방식으로 검토
- 60% 이상이 교육과정에서 다시 사용할 의향 표시
- 정성 인터뷰에서 구매자와 사용자의 핵심 불편을 각각 3개 이상 확보

목표치는 실적이 아니다. 실제 원자료와 표본 수를 함께 공개한다.

## 9. 단계별 실행

### 1R · 문제와 고객 검증

- 렛유인 학생 파일럿 5–10명
- 학생 인터뷰와 교육담당자 인터뷰
- 산업동향·용어·SCM·기업정보 니즈의 우선순위 검증
- 기업·공정·직무를 잇는 Industry Twin 클릭형 시제품 검증
- 사전·사후 평가 문항의 전문가 검토
- 이탈구간·오류·AI 검토 행동 분석
- 초기 로딩과 모바일 사용성 개선

### 2R · 기관용 MVP

- 익명 학습 이벤트 로그
- 산업데이터 게이트웨이와 반도체 지식그래프

- 강사용 대시보드
- 사전·사후 진단과 평가 리포트
- 공정 시나리오 저작 규격
- 운영자 API 방식과 비용통제
- 개인정보·보안·접근성 검토
- 교육기관 기수 단위 실증

### 2R 기술개발 목표

- 시나리오 정의 스키마와 자동 유효성검사
- seed 100회 반복 시 데이터·정답 hash 일치
- 정답누설·프롬프트 공격 회귀시험
- 익명 append-only 학습 이벤트 로그
- 공공데이터 수집일·출처·스키마 버전 관리
- 기업·용어·공정·제품 관계의 provenance 및 신뢰등급 관리
- 공시에서 확인되지 않은 고객·공급관계의 사실 단정 방지시험
- 강사가 코드 수정 없이 사건·함정·rubric을 편집하는 저작도구
- 20명 동시 수업에서 세션 유실·중복 0건 검증

## 10. 지원금 사용 원칙

- 고객·문제 검증과 파일럿 운영
- 사전·사후 진단 및 강사 평가도구
- 서버 운영·보안·접근성
- 초기 로딩 성능과 모바일 품질
- 기관용 대시보드와 시나리오 저작규격
- 데이터·채점 엔진의 재현성·보안·부하 시험
- 공공데이터 provenance와 API 변경 대응 계층

대형 3D 자산 제작은 학습효과와 구매의향 검증 이후로 미룬다.

## 11. 주요 위험과 대응

- **회사 기밀 오인:** 합성 데이터, 공개자료, 비공식 교육 고지를 유지한다.
- **산업정보 환각:** 출처 없는 사실 저장을 금지하고 공식 확인·분류·추론을 화면에서 구분한다.
- **외부 API 변경:** 검증 스냅샷, 스키마 버전, 계약시험과 갱신 실패 경고를 둔다.
- **AI 정답 의존:** 경쟁 가설·반증·사람 검증을 다음 단계 진행조건으로 둔다.
- **교육 효과 과장:** 사전·사후 원점수와 표본 수를 공개하고 취업 합격을 보장하지 않는다.
- **개인 API 키 위험:** 키 비저장·HTTPS·수동 복사 방식 제공, 파일럿에서는 키 입력을 필수로 하지 않는다.
- **재직자 이해충돌:** 회사 시간·장비·계정·데이터를 사용하지 않고 취업규칙과 겸직 절차를 확인한다.
- **이종창업 자격:** 기존 사업자 업종 추가 전에 주관기관의 공식 답변을 받는다.

## 12. 신청서 이미지 10장 구성

1. 팹 경험과 산업맥락의 이중 격차
2. 학생이 요구하는 산업동향·현업 용어·SCM·기업정보
3. `산업 이해 → 가상팹 판단 → 역량 증명` 전체 흐름
4. 출처·기준일이 표시된 Industry Brief
5. 고객·Fab·장비·재료를 잇는 SCM Map과 신뢰등급
6. 2,969행 합성데이터 분석과 `radius_mm` bin
7. AI 심층문답·사람 검증·Holdout
8. 서버 역량 증거와 면접 PT
9. 렛유인 학생 파일럿 설계
10. 기술구조·사업모델·실행일정·지원금 사용

## 13. 제출 전 필요한 입력

- 공식 신청서 문항과 항목별 글자 수
- 기창업자 이종창업 인정 방식에 대한 주관기관 답변
- 재직자 단계별 상근·전업 의무에 대한 주관기관 답변
- 유사 정부과제와 중복수혜 여부 확인
- 렛유인 파일럿 승인 및 자율 참여자 모집 가능 여부
- 학생 인터뷰·파일럿 원자료
- 교육기관 지불의향과 예상 가격 단위

위 입력을 확보한 뒤 공식 문항별 최종본으로 재작성한다.
